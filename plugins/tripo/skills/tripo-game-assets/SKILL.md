# Game assets with Tripo

Tripo's own MCP tools (from Tripo's `tripo-cli`) are connected as `tripo`, on the Tripo API key saved on the plugin's card in Settings → Plugins. Never call `curl` with the key, ask the person for it, or run `tripo login`.

1. **Use Ramu's `make_model` tool.** It runs on Tripo (model H3.1), waits for the task, downloads the GLB and keeps it as an attachment (and at `assets/models/<name>.glb` in a project). `prompt` names one subject with its style and materials ("a low-poly cartoon fox, orange and white"). Tripo is strongest from a picture: pass `image` (an attachment, such as a photo the person sent or concept art from `generate_image`) showing one subject on a plain background with the whole object in frame.
2. **Calling Tripo yourself** (for what `make_model` does not take, or when it says the tool takes no image, as older Ramu versions do): call `tripo_image_to_3d` with `input` set to the image's absolute file path and `model: "v3.1"`, then `tripo_task_wait` with the task id until `status` is `success` (each call waits under a minute; call it again while the task runs), then `tripo_download` with `output_dir` set to the project's `assets/models/<name>`.
3. **Budget triangles.** `detail: "low"` (about 5,000 triangles) for phone games and anything repeated, `"medium"` for a hero model. Keep a phone scene near 50,000 triangles. Calling Tripo yourself, `face_limit` sets the budget and `smart_low_poly: true` gives game-style low-poly topology (500 to 20,000 faces).
4. **Rig and animate.** `tripo_rig_check` on the model's task id says whether it can be rigged and as what body type (free to ask, before spending on a rig). Then `tripo_rig` with that `rig_type`, then `tripo_animate` on the rig task with presets such as `preset:idle`, `preset:walk`, `preset:run` and `preset:jump` (up to five in one file; `animate_in_place: true` when game code moves the character). Wait and download each as in step 2.
5. **More of Tripo's tools**, approved like any MCP call: `tripo_texture` (retexture, PBR), `tripo_convert` (FBX, OBJ, USDZ, STL), `tripo_decimate`, `tripo_smart_uv`, `tripo_segment` (split into parts), `tripo_multiview_to_3d` (front, left, back and right views), `tripo_import_model` (start from a model file), and `tripo_task_list` for tasks made before; reuse a model instead of making it again.
6. **Use the model.** In three.js load it with `GLTFLoader` (`import fox from './models/fox.glb'` in an App) and play clips with `THREE.AnimationMixer`; in Godot put it in `res://assets/models/`; in Unity in `Assets/Models/` with glTFast.
7. **Credits.** Every task spends the person's Tripo credits: H3.1 (`v3.1`) costs about 10 to 50 per model, and Tripo's default P2 about 100 to 130, so pass `model: "v3.1"` unless the person asks for P2's cleaner topology. For a job of several steps, call `tripo_plan` (free) and tell the person the steps and what they cost before running them; `dry_run: true` on a generation checks it for free. `tripo_balance` reads what is left and `tripo_usage` what a task cost. If a call stops for lack of credits, tell the person and carry on with shapes in code.
